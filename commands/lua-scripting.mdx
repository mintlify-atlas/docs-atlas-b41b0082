The `exec-safe` command lets a Console administrator remotely trigger a named Lua script on the receiver's client. Rather than sending raw Lua code over the network, `exec-safe` uses a name-based lookup — the receiver's mod holds the actual script, and the admin invokes it by name. This design keeps arbitrary code off the wire while still giving mod developers a flexible, scriptable execution hook on the receiver's end.

---

## `exec-safe`

```
exec-safe [Lua Script Name]
```

Runs a lua script in SafeLua by name on the receiver.

<ParamField path="Lua Script Name" type="string" required>
  The name of the Lua script to execute on the receiver's Console instance. Console performs a name-based lookup to find and run the script.
</ParamField>

<Warning>
  You **cannot** send arbitrary Lua code through `exec-safe`. Only scripts that have been pre-registered on the receiver's Console instance can be executed. Attempting to invoke an unregistered script name will result in a no-op on the receiver's end.
</Warning>

---

## Example

The following example triggers a script named `greetUser` on the receiver. The script itself is defined on the receiver's mod — the admin only sends the name.

```lua
-- Example SafeLua script: "greetUser" (defined on the receiver's mod)
notify("Hello from a Lua script!")
```

```csharp
// Trigger the pre-registered "greetUser" script on the receiver
Console.ExecuteCommand("exec-safe greetUser");
```
