After copying Console's source files into your project, two files require your attention before the library will work correctly: `Console.cs` and `ServerData.cs`. Each file contains a clearly marked `#region Configuration` block that groups every setting you are expected to change. Everything outside those regions is internal Console logic that you should leave untouched.

<Note>
  Because Console is embedded directly in your mod rather than loaded as a shared library, each project that integrates Console gets its **own independent copy** of these files. Changes you make are scoped to your mod only and will not affect other mods using Console.
</Note>

## Console.cs — Mod Identity and Command Handling

`Console.cs` is the main library file. Its `#region Configuration` block is where you tell Console which mod it belongs to and how incoming commands should be handled. Open `Console.cs` in your editor and search for:

```csharp
#region Configuration
```

All fields between that marker and the matching `#endregion` are yours to modify. Fill in each field according to the inline comments in the source. Do not rename or remove any field — only change the values assigned to them.

## ServerData.cs — Network and Authentication

`ServerData.cs` holds the networking configuration that Console uses to connect to its backend. Like `Console.cs`, all tunable settings live inside a `#region Configuration` block. Open `ServerData.cs` and search for:

```csharp
#region Configuration
```

Fill in each field with the values specific to your mod. Fields left at their defaults will prevent Console from connecting or authenticating correctly on startup.

<Warning>
  **Never commit real authentication keys or server credentials to a public repository.** If your source code is hosted on GitHub or any other public platform, an exposed key can be abused by anyone to impersonate your mod on the Console network. Rotate your keys immediately if they are accidentally published.
</Warning>

## Keeping Credentials Safe

For open-source mods, consider loading sensitive values at runtime rather than hard-coding them in the configuration region. This way your repository only ever contains placeholder strings and the real values never appear in version control.

## Frequently Asked Questions

<Accordion title="Do I need separate configuration for each mod I build?">
  Yes. Because you embed a full copy of Console's source in each project, every mod has its own `Console.cs` and `ServerData.cs`. Each copy should be configured independently so that admins can target individual mods separately.
</Accordion>

<Accordion title="What is the mod name field used for?">
  The mod name configured in `Console.cs` is returned as part of the `confirmusing` event when another Console user sends the `isusing` command to one of your players. Choose a concise, descriptive name that matches your mod's display name.
</Accordion>
