Console is a network-backed administrator library built for Gorilla Tag BepInEx mods. It gives mod developers a shared command channel that authorized administrators can use to interact with any player who has Console installed and running in the same room. Whether you want to send real-time notifications, teleport players, manage audio and visuals, or handle room moderation, Console provides the infrastructure to do it — all without building a networking layer from scratch.

## What Console Does

Console operates on a clear authority model: **admins execute commands, users receive them**. When a player installs Console as a mod, they join the network as a receiver. Administrators — those granted authority through the system — can then issue commands that are delivered over the network to targeted receivers in real time.

This separation means that simply having Console installed does **not** grant any special powers. Commands only flow when the sender holds the appropriate authority, which keeps the system controlled and intentional.

<Note>
  You must have admin authority on the Console network to execute commands. Installing Console as a user only enables you to *receive* commands issued by authorized administrators.
</Note>

## How It Works

Console runs as a BepInEx plugin inside Gorilla Tag. When your mod calls `Console.LoadConsole()`, it initializes the network connection and registers the necessary components. From that point on, the `HamburburData` component handles incoming and outgoing data packets, while `TrackerManager` monitors the Console users present in the room.

Administrators issue commands using `Console.ExecuteCommand()`, passing a command string that targets the current receiver. Commands can be as simple as sending a notification or as complex as spawning a networked asset at a specific position and rotation.
